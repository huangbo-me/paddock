# 爱发电收款与离线发码

本次交付为 PadDock 0.2.0 内测：14 天试用、当前商业版本线 1 离线激活、购买入口和批量发码工具已实现。尚未创建爱发电商品，因此真实付款、自动发码和订单库存消耗尚未验收，当前包的购买按钮禁用。正在运行的 0.1.0 没有被替换。

## 已准备的文件

以下路径均相对于 PadDock 仓库：

| 文件 | 用途 |
| --- | --- |
| `dist/PadDock-0.2.0-arm64.dmg` | 内测安装包 |
| `.private/afdian-codes-batch-001.txt` | 100 个不同的可售激活码，一行一个 |
| `.private/owner-license.txt` | 一个开发者自用码，不导入销售库存 |
| `.private/signing-key` | 发码私钥，仅开发者保管 |
| `Resources/Commerce.json` | 公钥、商业版本线、商品地址，可随 App 分发 |
| `.build/tools/paddock-license` | 开发者发码工具，不随 App 分发 |

`.private` 目录权限为 0700，私钥及码库权限为 0600，已加入 Git 忽略。请将整个目录备份到自己控制的加密存储；现有文件不会被工具覆盖。不要重建或更换私钥，否则已售激活码与新公钥不匹配。码库等同于可售库存，不要公开分享或放进安装包；私钥绝不能上传爱发电。

## 上架步骤

1. 在爱发电完成自己的创作者设置，创建数字商品，建议名称为「PadDock 当前大版本离线授权」。价格由你决定；明确是一次购买，不要误设为自动续费产品。
2. 在说明中写清 Apple Silicon/macOS 14+ 的编译要求、已测试设备范围、登录之后才能自动运行、系统私有接口兼容风险，以及内测安装限制。建议让用户先试用自己的设备再购买。此构建尚未经过 Developer ID 签名和公证，不能当作已经可公开发行的正式版。
3. 配置商品的自动随机回复，把 batch-001 文件导入为每行一个完整激活码。不得把一个码换行，不要把整个库存作为普通固定回复。平台官方指南确认支持数字商品及逐行发码；实际后台字段、库存耗尽及去重行为仍要在你的账号中验收。[爱发电官方创作者指南](https://guide.afdian.com/creator/creator-level-up)
4. 在商品说明或通用通知里提示：「付款后查看自动私信中的激活码，在 PadDock → 购买与激活中完整粘贴 PD1. 开头的内容。」给出下载地址和自己的客服方式。不要把私钥或开发者自用码填入商品资料。
5. 把真实商品链接写入配置并重新打包。该步骤不需要 API Token 或服务器。下方 URL 只是格式示例，不要直接用作正式商品地址。

```sh
cd /Users/bobo/Documents/Playground/PadDock
bash scripts/build-license-tool.sh
.build/tools/paddock-license set-purchase-url Resources/Commerce.json 'https://afdian.com/item/你的真实商品ID'
bash scripts/build.sh
bash scripts/package.sh
bash scripts/verify-artifacts.sh
```

只接受 `https://afdian.com/.../...` 或 `https://afdian.net/.../...` 的具体路径。商品尚未上线时保留空字符串。更改链接后必须重新构建，现有安装包不会远程更新。

## 发码与补库存

当前密钥和首批码已经生成，**不要再次执行 keygen**。追加下一批时用新文件名：

```sh
.build/tools/paddock-license issue .private/signing-key 100 .private/afdian-codes-batch-002.txt
.build/tools/paddock-license verify Resources/Commerce.json .private/afdian-codes-batch-002.txt
```

命令只输出数量，不显示私钥或激活码。工具拒绝覆盖已有库存文件，拒绝读取对其他用户开放权限的私钥。请记录每批导入日期、数量和对应商品，避免重复导入同一批；平台库存归平台管理，本地工具不读取已售订单。退款或纠纷后不能远程使离线码失效，不承诺一机一码。

## 离线版边界

许可证只在本机用公钥验签，不会联系爱发电验证订单，所以码可复制、无法远程吊销；本机管理员也可能绕过试用。到期不会断屏或移除虚拟屏。手动恢复始终保留；已配对的无显示器模式在无法证明另有可用屏幕时继续自动恢复。当前仅认可在线内置屏幕作为证据，因此 Mac mini 的已配置无显示器恢复采用宽松授权限制。这是保护唯一屏幕的明确取舍。
